## 2026-11-18（续7）：CI 集成测试依赖固化（22 用例 CI 全绿）

### 问题
CI 干净环境运行 DB 集成测试时，EF Core 传递依赖版本与主程序还原版本不一致，
先后报 `DiagnosticSource`/`Microsoft.Data.Sqlite`/`Caching.Abstractions`/`ComponentModel.Annotations` 缺失或版本不符。
根因：产品依赖图混乱（R016/R017）——`Zoncare.DAL` 用主程序还原的版本集（Sqlite 9.0.3 + EF Core 2.2.6 + DiagnosticSource 6.0.0.2）编译，
测试工程若单独还原会得到不同版本，运行时 bindingRedirect 又缺失。

### 尝试与放弃的方案
- PackageReference 精确引用 EF Core 2.2.6 → 与 Zoncare.DAL(用 9.0.3 编译) 冲突 CS1705 + batteries_v2 CS0433，放弃。
- 从主程序 bin 复制 → CI 版本漂移，放弃。

### 最终方案（已采用）
- 将本地验证通过的运行时依赖闭包（125 个 DLL，8.78MB）固化到 `TEST/UnitTests/runtime-deps/`。
- 测试工程编译引用（Microsoft.Data.Sqlite/SQLitePCLRaw/EF Core）+ AfterBuild 复制，全部指向该固定目录。
- 效果：本地与 CI 使用完全相同的 DLL 版本组合，彻底消除环境差异。
- app.config 保留 bindingRedirect（DiagnosticSource/Sqlite/Annotations 等），与主程序一致。

### 验证结果
- **全新干净目录编译 + 运行：22/22 通过**（精确模拟 CI 干净检出，非增量编译）。
- GitHub Actions run 44238379602：`conclusion=success`，22 用例 CI 全绿。

### 影响范围
- 新增 `TEST/UnitTests/runtime-deps/`（125 DLL，二进制依赖固化）；修改 csproj、ci.yml。
- 未改产品源码/csproj。

### 说明
- runtime-deps 固化是应对产品依赖混乱(R016/R017)的临时工程手段；根本修复是统一产品依赖版本后移除固化。
- 这些 DLL 多为带已知漏洞的旧版本（见 R014/R015），固化仅为让测试可重现，不影响产品发布产物。
