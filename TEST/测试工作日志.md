## 2026-11-18（续）：P0-1 构建环境搭建

### 改动内容
1. 管理员静默安装 **VS Build Tools 2022**（MSBuild 17.14 + .NET 桌面构建工作负载 + .NET 4.6.2 目标包 + NuGet + 测试工具），装于 `D:\VSBuildTools2022`，C 盘保留共享组件。跳过 C++ 工作负载。
2. 下载还原 `System.ValueTuple 4.5.0` 包至 `packages\System.ValueTuple.4.5.0`（并在包内补 `lib\net46` 目录，因包仅含 net461）。
3. 新建 `packages\NetStandardFacade\netstandard.dll`（从本机 4.7.2 目标包复制的外观程序集）。
4. 新建项目根 `Directory.Build.props` —— 构建适配层（详见下）。
5. 对 `Zoncare.DAL` 执行 NuGet Restore，还原 EF Core / SQLitePCLRaw 等 PackageReference 依赖。

### Directory.Build.props 作用（为什么改）
项目长期未在干净环境编译，存在多处依赖缺失/版本冲突，均通过构建适配层解决，不改任何产品 csproj/源码：
- `netstandard.dll`：4.6.2 目标包缺该外观程序集，EF Core(.NET Standard 2.0) 编译必需。
- `System.ValueTuple` 统一为 4.0.3.0：多个项目用元组但无引用；启动项目自带 4.0.2.0 与依赖项目冲突（CS1705）。
- `System.IO.Compression` / `.FileSystem`：启动项目 `DataTransferHandlerNew.cs` 用 `ZipArchive` 但未引用。
- 剔除 `SQLitePCLRaw.bundle_green 1.1.12` 的 `batteries_v2`：EF Core Sqlite 2.2.6 传递依赖的旧版与项目直接引用的 2.1.10 类型冲突（CS0433）。

### 影响范围
- 新增/修改：`TEST/` 文档、`Directory.Build.props`、`packages\System.ValueTuple.4.5.0\`、`packages\NetStandardFacade\`、`Zoncare.DAL\obj\*`（还原产物）、各项目 `bin\Release\`（编译产物）。
- **未改动任何产品源码或 csproj**；`Directory.Build.props` 只影响编译期。
- 系统级：安装 VS Build Tools 2022，占用 D 盘约 1GB+，C 盘共享组件约 1GB。

### 验证结果
- 完整解决方案 Release|Any CPU 编译**成功**，全部项目产出：
  `EcgBpAnalysis.exe`、`AnalysisApp.exe`、`UpgradeTool.exe` 及全部依赖 DLL。
- 还原时 NuGet 报告 2 个高危漏洞包：`Newtonsoft.Json 12.0.2`、`SQLitePCLRaw.lib.e_sqlite3 2.1.10`（已记入审查台账 R014/R015）。

### 待办
- 建正式测试工程（NUnit/MSTest + Moq），可复用本机 MSBuild 17.14 + 已装的测试工具组件编译运行。

### 覆盖内容
- 16 字节 nibp 记录字段偏移契约、checksum 篡改检测、单位换算 ×1000。
- 8337 的 22 字节记录长度与年份偏移、文件长度整数倍校验。
- nibp 文件名时间串解析、非法时间串拒绝、非法日期抛异常。
