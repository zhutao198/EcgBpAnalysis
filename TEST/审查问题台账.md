## 二、问题清单

### R001 — 血压 interop 输出缓冲区可能越界（内存安全）
- **文件**：`AnalysisApp/Commons/BpPulseWaveDataHandler.cs:26-36, 61-68`
- **级别**：阻断（Blocker）
- **描述**：`dcPtr`/`acPtr`/`fitCurveXPtr`/`fitCurveYPtr` 按 `arrData.Length` 分配，但回读时按 native 返回的 `outputWave.len` 拷贝（`Marshal.Copy(..., dc.Length)`），**未校验 `outputWave.len <= arrData.Length`**。若 native 返回更大的 len，将越界读取非托管内存，导致数据损坏或进程崩溃。`stepDc`/`stepDcLen` 按固定 100 分配（`stepDcPtr` :33-34），回读按 `outputWave.stepLen`，**同样未校验 `stepLen <= 100`**。
- **影响**：患者血压数据错误 / 应用程序崩溃（医疗软件高危）。
- **建议**：回读前增加边界断言 `outputWave.len <= arrData.Length && outputWave.stepLen <= 100`，越界时记日志并返回错误码；与 native 约定缓冲区容量契约。
- **同类问题**：`EcgAnalyseStart/sundries/DataHandler.cs:365-402` 存在完全相同的缺陷（重复代码）。
- **状态**：待确认（需结合 native 接口定义确认契约）

### R002 — P/Invoke 结构体字段初始化不完整 / 布局契约未验证
- **文件**：`BpPulseWaveDataHandler.cs:23,39-42,92-101`
- **级别**：严重（Major）
- **描述**：`nibpInData` 定义 6 个字段（`preWave/stage/len/refPR/refHR/cl`），但 `WaveDataPlot` 仅赋值前 4 个，`refHR` 与 `cl` 未显式初始化。`new nibpInData()` 会零初始化，但 native 是否期望有效的心率参考值与置信度未知。此外 `nibpOutFittingCurve` 声明了 `SBP/MBP/DBP` 输出字段，但本函数**完全未使用拟合曲线结果**（`outputCurve` 传入后未读取 SBP/MBP/DBP）。
- **影响**：算法输入参数不完整可能导致拟合异常；血压计算结果疑似未在 interop 层获取。
- **建议**：与 native 头文件逐字段核对结构体布局（`StructLayout`/字段顺序/类型）；确认 `refHR`/`cl` 的传递要求；确认 SBP/MBP/DBP 结果是否应在其他函数获取。
- **状态**：待确认

### R003 — CRC 校验可绕过：大文件直接跳过且返回成功
- **文件**：`AnalysisSystem.Base/FileDataHandler.cs:25,60,70`
- **级别**：严重（Major）
- **描述**：`Crc32Verify` / `Crc32Verify_IE95` 中 `if (fi.Length < 524288000)`（500MB）之外的大文件**不做任何校验**，函数最终仍 `return true`。动态心电 24h 数据可能超过该阈值，损坏数据可能被当作有效数据入库。
- **影响**：数据完整性风险，可能基于损坏波形出具错误诊断报告。
- **建议**：明确该阈值的业务意图；若为防止内存溢出，应改用流式 CRC 而非整体跳过；跳过时至少记录日志并向调用方返回"未校验"状态。
- **状态**：待确认（需确认 500MB 阈值设计意图）

### R004 — 血压文件时间解析失败污染数据
- **文件**：`FileDataHandler.cs:98-100, 155-156`
- **级别**：严重（Major）
- **描述**：`ParseBpFile` 中 `DateTime fileTime = DateTime.Now;` 后用 `TryParseExact(..., out fileTime)`，解析失败时 `fileTime` 被置为 `DateTime.MinValue`（0001-01-01），仍被写入 `abpData.OriginalTime/time`——与注释期望的"用 Now 兜底"相反，产生错误时间戳。`ParseBpFileFor8337:156` 使用 `new DateTime(y,mth,d,h,m,s)`，设备上报非法日期（如月=13）会抛异常，被外层 catch 吞掉（`:181-185`）并返回 null，导致整批数据丢失且仅记一条日志。
- **影响**：血压记录时间错误或整批记录丢失，影响趋势图与报告。
- **建议**：解析失败时明确兜底策略（跳过该条 / 用文件名时间 / 用 Now）并记录；对非法日期逐条校验跳过而非中断整批。
- **状态**：待修复

### R005 — 血压文件长度未校验即解析
- **文件**：`FileDataHandler.cs:83-93, 127-133`
- **级别**：严重（Major）
- **描述**：`ParseBpFile` 直接 `offset = dataBytes.Length - 16` 并 `BitConverter.ToInt16(dataBytes, offset+14)`，**未校验文件长度 ≥ 16**；短文件/损坏文件会抛 `ArgumentOutOfRangeException`。`ParseBpFileFor8337` 虽有 `Length < 22` 校验（:128），但循环步长 22，尾部不足 22 字节的残片会被 `i+21` 越界读取。
- **影响**：损坏 SD 卡文件导致解析崩溃。
- **建议**：解析前校验长度下界与 `(Length % 16/22)` 完整性；尾部残片明确丢弃并记日志。
- **状态**：待修复

### R006 — 硬编码数据库加密密钥
- **文件**：`Zoncare.DAL/ZoncareModels.cs:22`、`ZoncareModelsPlus.cs:16`
- **级别**：严重（Major，安全）
- **描述**：SQLite 加密口令 `ACCESS_KEY = "zq2877"` 以明文常量硬编码在源码中，随程序分发即可被逆向获取，数据库加密形同虚设。涉及患者隐私数据。
- **影响**：患者隐私数据泄露风险；不符合医疗软件数据安全要求。
- **建议**：密钥外置（配置/密钥容器/加密狗），至少做混淆并与设备绑定；评估合规要求。
- **状态**：待确认（需评估合规与改造成本）

### R007 — FunctionPercents 跨线程字典读写竞态
- **文件**：`AnalysisApp/Commons/aEcgHandler.cs:333, 390, 435, 1627-1659`；`AnalysisApp/ReanalysisPage.cs:179`
- **级别**：严重（Major，并发）
- **描述**：`public static Dictionary<...> FunctionPercents` 由 native 回调线程写入（`:1659`，有 `_lockObj` 包裹），但 `LoadData:390`、`Reanalyze:435` 的写未加锁，`ReanalysisPage.cs:179` 的读（UI 线程 `TryGetValue`）也未加锁。.NET `Dictionary` 非线程安全，并发读写可能导致数据损坏或无限循环。
- **影响**：进度显示异常 / 偶发死锁或崩溃。
- **建议**：统一用 `ConcurrentDictionary`，或读写全部纳入同一把锁。
- **状态**：待修复

### R008 — Init/DeInit 生命周期缺少幂等与失败检查
- **文件**：`aEcgHandler.cs:349-364`
- **级别**：严重（Major）
- **描述**：`Init()` 未检查 `aecgInit` 返回值是否为 `IntPtr.Zero`（初始化失败）；`DeInit()` 无条件 `_gcHandle.Free()`，若未 Init 或重复 DeInit 会抛 `InvalidOperationException`。
- **影响**：库加载失败时后续调用空指针；重复释放导致异常。
- **建议**：Init 检查返回并记日志；DeInit 增加 `_aecgPtr != Zero`、`_gcHandle.IsAllocated` 判断并置零，保证幂等。
- **状态**：待修复

### R009 — HandleProcessCorruptedStateExceptions 掩盖 native 内存错误

### R018 — 大量 HintPath 指向 bin/ 或仓库外部路径（CI 不友好）
- **文件**：`Zoncare.Common.csproj:58,61,68,71`、`SystemSettings.csproj:59,62`、`AnalysisApp.csproj:67,71,79,83`、`AnalysisSystem.Base.csproj:57`、`UpgradeTool.csproj:40,42`、`ABPMRepository.csproj:77`

### R019 — 命名管道通信存在消息截断与线程安全风险
- **文件**：`Zoncare.Common/PipeCommunication.cs`（PipeServer / PipeClient）
- **级别**：严重（Major，并发/可靠性）
- **描述**：
  - `:57,87` / `:177,210`：用固定 1024 字节 buffer 读取，`PipeTransmissionMode.Message` 下若单条消息 >1024 字节会被截断；UTF-8 多字节字符在 buffer 边界可能被拆分导致乱码。
  - `:121-128` `SendMessage` 与 `ReadCallback`（`:103,218`）并发读写同一 pipe 流，无同步锁，存在竞态。
  - `:83,206` 回调用字段 `_pipeServer`/`_pipeClient` 而非回调状态/捕获变量，`Stop()`/Dispose 后回调触发可能访问已释放对象。
  - `:170` `Connect()` 无超时参数，`:52` `WaitForConnection()` 同步阻塞，异常时仅 `Console.WriteLine`，主程序缺乏可靠的握手失败反馈。
- **影响**：双进程通信（主程序 ↔ AnalysisApp）在主进程 → 分析进程协调时可能消息丢失、乱码或偶发崩溃。
- **建议**：改用消息帧（长度前缀）或足够大的缓冲区并按消息边界读取；收发加锁或分离读写流；回调捕获局部流引用并做 disposed 判断；Connect/WaitForConnection 增加超时与明确错误码。
- **状态**：待确认
