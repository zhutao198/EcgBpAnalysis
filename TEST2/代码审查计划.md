## 3. 项目特化审查清单（Checklist）

### A. P/Invoke 与 native 边界（最高优先级）
- [ ] `DllImport` 的 `EntryPoint` 是否真实存在于 DLL 导出表（**用 PE 导出表机械核对**，不靠推断）
- [ ] `CallingConvention` 与 C++ 导出约定一致（`__cdecl` / `__stdcall`；x64 下虽统一为同一约定，但 32 位构建需复核）
- [ ] `CharSet` 与字符串编码一致（`CharSet.Ansi` ↔ `char*`；`Unicode` ↔ `wchar_t*`）
- [ ] **结构体布局**：字段顺序、类型宽度、`Pack` 值与 native 一致（对照 `aecg_common.h`）
- [ ] **缓冲区契约**：`out IntPtr` / 指针数组的元素类型、数量单位（字节 or 元素）、容量上限、谁分配谁释放
- [ ] **越界防护**：回读长度是否校验 ≤ 分配容量；native 是否可能改写长度参数
- [ ] 同一 native 函数的**重复声明**是否一致（`Pack`/参数差异）
- [ ] DLL 位数（PE Machine）与宿主进程位数是否匹配（x86/x64 混用 → `BadImageFormatException`）
- [ ] 运行时依赖链（MinGW / VC runtime）是否随部署分发
- [ ] 回调 delegate 是否需要 `GCHandle` 固定；native 释放后是否仍可能回调

### B. 数据完整性与解析
- [ ] CRC 校验：开关语义、超大文件策略、INI 键缺失/格式异常的健壮性
- [ ] 二进制格式：字段偏移、校验和算法、单位换算（×1000 / mmHg↔kPa）、符号与字节序
- [ ] 时间：文件名解析、非法日期、时区、`DateTime.Now` 兜底污染
- [ ] 文件长度：是否校验整数倍/最小长度；残片文件的行为
- [ ] 解析失败：是否静默吞错；是否整批丢失；是否有日志且日志含上下文

### C. 报告正确性（直接影响临床判断）
- [ ] 模板占位符：键名唯一性（重复键 → 静默覆盖）、模板与代码键集合一致性
- [ ] 数值格式化：单位、精度、千分位、空值占位（NaN/∞/null 的呈现）
- [ ] 阈值比较：阈值与被比较值是否在同一单位域（mmHg vs kPa）
- [ ] 分页：边界条件（`idx == Count` vs `idx >= Count`）、空数据、空白页
- [ ] 图表/列表：空集合越界、固定索引访问、除零
- [ ] 签名位图：释放、非法 Base64 解码

### D. 并发、状态与生命周期
- [ ] 全局静态可变状态（`AnaValues` 等）的跨线程读写
- [ ] `Task.Run` / `async` 前后共享状态一致性
- [ ] 布尔忙碌标志 vs 计数器（嵌套调用提前清除）
- [ ] `DbContext` 生命周期：后台线程是否误用单例
- [ ] `ChangeTracker.AutoDetectChangesEnabled` 是否在所有路径恢复
- [ ] 资源释放：`FileStream` / `Bitmap` / SkiaSharp 对象 / `PrintDocument` / `Process`

### E. 进程与通信
- [ ] 命名管道：消息帧（>缓冲区截断）、收发并发、回调对已释放对象的访问、超时
- [ ] 子进程启动：提权参数与 `UseShellExecute` 的一致性、返回 null 判空、连接重试、退出清理幂等
- [ ] 等待循环：是否有硬超时与取消路径
- [ ] `DataServerListener`（TCP/HTTP 监听）：端口占用、并发连接、请求解析、异常隔离

### F. 数据库与安全
- [ ] `DbContext` 生命周期与线程安全；加密连接的密钥管理
- [ ] 升级脚本幂等性、白名单、防注入、失败回滚
- [ ] 硬编码密钥/口令
- [ ] 患者隐私字段是否落日志
- [ ] 依赖包已知漏洞

### G. 通用工程项
- [ ] 数组越界 / 空引用 / 除零 / 索引错误
- [ ] 硬编码路径与魔法等待（`Task.Delay(1000)`）
- [ ] 异常吞掉（空 catch）、仅 `Debug.WriteLine`（Release 丢失）
- [ ] TODO / 被注释掉的关键逻辑 / 未实现分支
- [ ] 重复实现（同一逻辑多处拷贝，易发散）
- [ ] 命名与可读性（仅在缺陷密度高的文件提）

## 4. 执行流程与角色

| 环节 | 内容 | 责任人 | 产出 |
|---|---|---|---|
| ① 范围确认 | 按上表锁定文件清单与配额 | 测试负责人 | 审查范围表 |
| ② 逐文件审查 | 按清单执行，记录到台账（文件/行号/级别/描述/影响/建议） | 测试负责人 + 审查子代理 | 台账条目 |
| ③ 契约机械比对 | 反射提取全部 `DllImport` 声明 → 与 PE 导出表/头文件自动比对 | 测试负责人 | 契约差异清单 |
| ④ 交叉复核 | 同一模块的多条发现交叉验证，避免误报 | 第二轮复核 | 误报剔除记录 |
| ⑤ 缺陷转化 | 台账 → 缺陷台账（含级别/优先级/状态/验证用例） | 测试负责人 | 缺陷单 |
| ⑥ 覆盖度核对 | 按 §2.2 配额核对，欠审补齐 | 测试负责人 | 覆盖度报告 |
| ⑦ 计划复核 | 与测试计划交叉，确认每个缺陷有对应测试或明确豁免 | 测试负责人 | RTX 矩阵 |

**缺陷分级**：
- **P0 阻断**：崩溃 / 患者数据错误 / 算法结果错误 / 内存破坏 → 阻塞发布
- **P1 严重**：主要功能受损 / 数据静默错误 / 安全漏洞
- **P2 一般**：边界/健壮性/可维护性
- **P3 建议**：命名、注释、风格

**状态**：新建 → 待确认 → 已确认 → 待修复 → 已修复待验证 → 已关闭 / 豁免（附理由）

## 5. 审查证据规范

每条发现必须包含：

```
ID | 文件:行号 | 级别 | 触发条件 | 实际行为 | 期望行为 | 影响 | 建议 | 状态
```

- **触发条件**必须具体到输入/状态（如"血压文件长度 45 字节"）
- **实际行为**描述代码真实执行路径，不猜测
- 影响分两类：**患者/数据影响**（医疗软件必写）与**工程影响**

## 6. 审查与测试的联动

| 审查发现类型 | 测试策略 |
|---|---|
| 纯逻辑缺陷 | 写单元测试锁定"正确期望"，使测试先失败（缺陷复现）→ 修复后转绿 |
| 边界/健壮性 | 写边界用例（空、0、负、极大、非法枚举、长度不足） |
| 契约类 | 写契约测试（反射 + PE 导出表 + 头文件三方比对） |
| 并发类 | 写并发压力测试（多线程重复执行 + 超时断言） |
| UI/真机类 | 写 UIAutomation 骨架 + 手工步骤，标记需真机 |
| 无法自动化 | 记入缺陷台账并标注"需人工验证步骤" |
