## 1. 测试策略与核心判断

### 1.1 项目可测性现实约束

| 约束 | 事实 | 策略后果 |
|---|---|---|
| 核心算法在 native DLL | `libaecg.dll`(x64)、`libnibp_dynamic_d_d.dll`(x64)，**无 C++ 源码**（`LibNibp.vcxproj` 指向仓库外 `F:\temp\figurePlot\`） | 算法数值正确性只能黑盒；**但 interop 契约可机械验证** |
| native 输入非标准格式 | `aecgLoadData` 读取病例目录（`holter.info` + `holter.dat`/`ecg_raw.dat`），工作区无任何病例数据 | golden 回归受阻 → 转而验证**契约层**与**C# 数据链路层** |
| 业务逻辑与 UI 深度耦合 | `CommonMethods.cs`(2022)、`EventCommonMethods.cs`(2143) 混杂 UI 操作与算法 | 需**可测性识别**：优先测纯函数；对耦合逻辑用**特征化测试** |
| 医疗软件 | 报告数值直接影响临床判断；数据错误 = 潜在伤害 | 数据链路一致性测试权重高于 UI 覆盖率 |

### 1.2 五层测试策略

```
L5 验收/临床场景  ── 手工（需真机+加密狗+设备）
L4 系统/UI         ── UIAutomation 自动化（需桌面会话）
L3 集成            ── 真实 DLL / SQLite / 文件系统 / 管道
L2 契约            ── P/Invoke 声明 ↔ 导出表 ↔ 头文件 三方机械比对 ★本轮重点
L1 单元            ── 纯逻辑、边界、算法、配置读写
```

### 1.3 本轮（TEST2）三项方法创新

| # | 方法 | 解决什么问题 | 自动化程度 |
|---|---|---|---|
| M1 | **interop 契约反射比对**：反射提取全部 `DllImport` 声明 → 解析 PE 导出表 → 与 `aecg_common.h`/`ecgAnalysis.h` 比对 | 人工无法可靠核对 40+ 声明 × 导出表 × 头文件三方一致性；自动化后可长期回归 | 全自动 |
| M2 | **数据链路端到端一致性**：构造二进制血压文件 → 解析 → 入库 → 查询 → 断言"写入值 == 读出值 == 报告用值" | 覆盖单点测试覆盖不到的跨模块漂移（单位、时区、字段映射） | 全自动 |
| M3 | **可测性静态识别**：按规则扫描源文件，标记纯函数候选（无 UI 依赖、无 I/O、无全局写） | 指导测试投入，避免在不可测区域浪费时间 | 半自动（辅助决策） |

## 4. 测试用例设计

### 4.1 L1 单元测试（按模块细化）

**4.1.1 CRC 与数据完整性（TC-CRC）**
- 标准向量 `"123456789"` → `cbf43926`
- 空数组、单字节、全 0xFF
- 确定性（同内容同结果）/ 区分性（差 1 bit 必变）
- 输出格式：8 位小写十六进制、无分隔符
- 文件级：真实文件（含中文名/大文件/二进制内容）哈希稳定

**4.1.2 血压数据格式（TC-BPFMT）**
- 16 字节记录字段偏移契约（checksum/motion/sys/dia/map/pr/err/left/measureType）
- 校验和 = Σ(字段) 规则；篡改任一字段必被检出
- 单位换算 ×1000；负值/极值语义
- 8337 的 22 字节记录：年份 = 2000 + byte[0]、长度整数倍、非法日期抛异常
- nibp 文件名：14 位时间串提取；月=13/日=32 拒绝

**4.1.3 通用工具层（TC-UTIL，新增）**
- 日期时间：格式转换、闰年、月末、跨年、`DateTime.Now` 兜底路径识别
- 字符串：中文/英文混排、空串、`null`、Trim、大小写
- 数值格式化：定点小数位、千分位、负数、零、单位后缀
- 进制/位运算：字节序转换、bit 掩码
- INI 读写：键缺失、重复键、中文值、空行、注释
- 文件：路径拼接、非法字符、已存在/不存在

**4.1.4 配置对象（TC-CFG，新增）**
- `HolterConfig` 序列化 → 反序列化 往返字段全等
- 缺字段/多字段/非法值 的容错
- `app-config.xml`、`dbCheck.json` 结构校验（字段完整性、标识符合法性）

### 4.2 L2 契约测试（TC-CONTRACT，本轮重点）
- **C-CONTRACT-01**：反射枚举 `aEcgHandler`/`BpPulseWaveDataHandler`/`DataHandler`/`DataFileHandler` 全部 `DllImport`，断言每个 `EntryPoint` 存在于对应 DLL 的 PE 导出表 → **自动发现不存在的 EntryPoint**
- **C-CONTRACT-02**：断言所有 `DllImport` 的 `CallingConvention` 与 `CharSet` 符合约定（C 头文件 `__cdecl` / `char*`）
- **C-CONTRACT-03**：断言同一 native 函数的多处重复声明参数与布局一致（`nibp_figure_plot` 两处 `Pack` 差异 → 暴露 R011）
- **C-CONTRACT-04**：C# 结构体字段与 `aecg_common.h` 结构体逐字段对齐（类型宽度、顺序、数量）→ 暴露 R002
- **C-CONTRACT-05**：native DLL 位数（PE Machine）与宿主位数一致
- **C-CONTRACT-06**：`libaecg` 核心导出符号存在（aecgInit/Deinit/LoadData/Reanalyze/GetBeatsInfo/CalculateHRV/…）
- **C-CONTRACT-07**：头文件已声明但 C# 未导入的函数清单（信息性，防遗漏能力）
- **C-CONTRACT-08**：运行时依赖闭包完整（MinGW/VC runtime 可解析）

### 4.3 L3 集成测试（TC-INT）
- **血压解析全链路（M2 核心）**：构造二进制 → `ParseBpFile` → 入库 → 查询 → 断言「文件字段 == 入库值 == 查询值」，覆盖单位/时间/字段映射
- 8337 多记录批量导入：全部入库、顺序、批量条数
- 非法记录混入：合法记录不丢失（当前实现为整批 catch → 记录为缺陷）
- DB 升级幂等：重复执行、字段已存在、schema 缺失
- 命名管道：消息往返、并发读写、大消息（特征化当前行为）
- native 加载与调用（`aecgVersion`）

### 4.4 L4/L5 系统与验收
- UIAutomation 冒烟：启动、顶层窗口、主窗体关键控件
- 真机骨架：SD 卡导入→分析→报告、双进程握手超时、kPa 标记、加密狗缺失、位数不匹配

## 7. 缺陷管理

**分级**：P0 阻断（崩溃/患者数据错误/算法错误/内存破坏）｜P1 严重（功能受损/数据静默错/安全）｜P2 一般（边界/健壮性）｜P3 建议

**流程**：提报 → 分级 → 定责 → 修复 → 回归 → 关闭；每轮产出缺陷趋势与遗留风险。

**本轮约束**：用户要求「先不修复产品代码」→ 缺陷全部登记待开发团队处理，测试侧提供**可复现的失败测试**作为验收依据。

## 9. 可追溯性（RTX）

建立三向映射：

```
审查发现 R-xxx  ──┬── 缺陷 DEF-xxx ── 验证用例 TC-xxx-xx
                  └── 需求/风险条目
用例 TC-xxx-xx  ──┬── 被测代码文件:行号
                  └── 关联缺陷
```

RTX 矩阵是医疗软件审计核心产物，覆盖率统计随每轮更新。

## 11. 风险与应对

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| native 无源码，算法正确性无法验证 | 高 | 高 | 转向契约层 + C# 数据链路层；向算法团队提数据需求 |
| 业务逻辑与 UI 强耦合，难以单测 | 高 | 中 | 优先纯函数；耦合逻辑用特征化测试锁定当前行为 |

| 审查子代理可能产生误报 | 中 | 中 | 交叉复核 + 证据规范（须给行号与触发条件） |
| 报告类缺陷需肉眼比对，自动化难 | 中 | 中 | 先做数值/单位/边界的自动断言，视觉项转手工 |
